# Лабораторная работа № 3. Модульное тестирование

Цель работы — проверить приложение из лабораторной № 2. Тесты находятся в `shop/tests/`.

| Что проверяется | Как проверяется |
| --- | --- |
| Количество и сумма товаров, пустая корзина | Тесты расчётов без базы данных |
| Подбор товаров для корзины | Подмена запроса к каталогу через `unittest.mock.patch` |
| Оформление заказа | В модульном тесте обработчика подменяется сервис заказа; в отдельном тесте проверяется запись в БД |
| Ошибка записи позиции | Подмена `bulk_create` исключением; проверка отката транзакции |
| Каталог, регистрация, вход и выход, корзина, история | Запросы через тестовый клиент Django |

Для запуска достаточно зависимостей из `requirements.txt`:

```powershell
.\.venv\Scripts\python.exe manage.py test -v 2
```

Django поднимает отдельную тестовую базу. Тесты не изменяют данные магазина.

Результат: **17 тестов прошли**. Покрытие кода приложения — **99%** по строкам (`coverage.py`, без миграций и файлов тестов).

## Вывод

Моки изолируют обработчик оформления от записи заказа. Тесты с базой проверяют сохранение цен, откат заказа при ошибке и ограничение доступа к истории покупок. Тестовый клиент дополнительно проверяет, что маршруты, сессия и шаблоны работают вместе.
